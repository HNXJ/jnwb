# Cooperation between concurrent agents

How two or more agents work on this repository at once without drifting apart. Ruled by Hamm on
2026-09-25: one **integrator** and any number of **workers**. The project-state files are the
only shared truth; messages carry claims and handoffs, never state.

## Roles

| Role | Holder | Does | Never |
|---|---|---|---|
| Integrator | the local Claude Code session on this machine | the only writer on `C:/workspace/jnwb` and `dev`: applies stack edits, integrates workers' commits, pushes, releases | certifies a worker's commit without an independent verification |
| Worker | any other session, e.g. a cloud Cowork session | reviews read-only, executes claimed packets in its own clone, proposes stack edits | writes to the integrator's tree or `.git`: no `worktree add`/`prune`, `status`, `fetch` or commit there |
| Hamm | the maintainer | owns goal and fact, rules decision points, approves PyPI | |

## The shared files

| File | Writer | Everyone else |
|---|---|---|
| `artifacts/goal.md` | Hamm | reads |
| `artifacts/fact_stack.md` | Hamm | reads; challenges it with evidence through the bus |
| `artifacts/todo_stack.md` | integrator | proposes edits as bus messages or bundles |
| `artifacts/problem_stack.md` | integrator | proposes rows and triage as bus messages |
| `artifacts/state.md` | generated by `scripts/reconstruct_state.py` | regenerates it in its own tree; never copies or quotes a stale one |
| memory | each agent its own | never writes another agent's memory. A lesson both need becomes a rule in `AGENTS.md` or here |

A claim about state is read from these files at the commit named, never from a message or from
memory. A message that disagrees with a file loses.

## The bus

`F:/cowork/jnwb-bus/`, outside git and visible to every agent. One outbox per agent
(`<from>_to_<to>.md`), with a single writer per file and append-only entries. Each message is headed
`## <UTC> #<n> <from>`, a reply cites `re #<n>`, and completed work is marked `ack #<n>`. Nothing
notifies an agent of a new message: Hamm says "check bus", or a scheduled task reads it.

## Claiming work

1. The worker posts `claim <item>` with its baseline commit and the exact Writes paths.
2. The integrator answers `ack` or `wait <reason>`. Claims whose Writes overlap wait. The
   integrator does not edit a claimed path until it is released.
3. The worker executes in its clone, then posts the commit SHAs and a bundle
   (`git bundle create <bus>/<packet>.bundle <baseline>..<branch>`).
4. An agent that wrote none of it verifies the work, killing a mutant where behaviour changed.
   Only then does the integrator cherry-pick, one commit per command, and delete the finished
   item from the todo stack.

A packet is `{goal, baseline, reads, writes, accept, stop}`. `stop` names the conditions under
which the worker reports instead of acting: a library change it was not given, a scientific or API
choice, or evidence that conflicts with a higher authority (`AGENTS.md` §12).

## Standard tasks

| # | Task | Who | Trigger | Output |
|---|---|---|---|---|
| T1 | Stack hygiene: pointers resolve, no finished items remain, parsed fields parse, every problem row is triaged, the todo stack's version headings match the package version | worker | daily, scheduled | findings and proposed edits on the bus; the integrator applies them |
| T2 | Independent review of the commits integrated since the last review | worker | on request | verdict per commit, with receipts |
| T3 | Triage proposal for problem rows under the blocker predicate (`AGENTS.md` §11) | worker | when the problem stack is not empty | `required` or `deferred` per row, with the predicate clause; the integrator or a critic decides |
| T4 | Execute one todo item as a packet | either role, by claim | manual | commits and a bundle (worker) or commits on `dev` (integrator) |
| T5 | CI watch; diagnose a red run | integrator | after each push | a repair, or a row in the problem stack |
| T6 | Memory curation: promote a recurring lesson to a rule, archive a stale one, delete a wrong one | each agent, own memory only | weekly, scheduled | a short note on the bus of what was promoted |
| T7 | Release checklist (`CONTRIBUTING.md`) | integrator | Hamm | the release |

## Conflicts

The authority order is that of `AGENTS.md` §1: the receipt on disk, then live repository state,
then machine-readable state files, then prose and messages. An agent that finds a conflict on a
material point stops and posts both sides; it does not resolve it silently. Two claims on one item,
or a claim over a path the integrator is editing, resolve in favour of the earlier `ack`.
